什么是Kubernetes

Kubernetes的起源

Kubernetes（简称K8s）源自Google内部的容器编排系统Borg，2014年开源，现由CNCF（云原生计算基金会）维护。名字来源于希腊语，意为”舵手”或”飞行员”。

为什么需要Kubernetes

当容器数量从几个增长到成百上千时，手动管理变得不可能。Kubernetes解决了以下核心问题：

核心价值

Kubernetes的核心价值在于声明式配置和自动化运维。你只需告诉K8s你想要什么状态，它会自动确保达到并维持该状态。

Kubernetes架构

整体架构

Kubernetes采用Master-Worker架构，由控制平面（Control Plane）和数据平面（Data Plane）组成：

组件作用说明

Cloud Controller云平台对接与云服务商API交互

环境搭建

本地开发环境选择

Minikube 是官方推荐的本地Kubernetes环境，适合学习和开发。

# macOS安装
brew install minikube

# Linux安装
curl -LO https://storage.googleapis.com/minikube/releases/latest/minikube-linux-amd64
sudo install minikube-linux-amd64 /usr/local/bin/minikube

# Windows安装（PowerShell管理员模式）
choco install minikube

# 启动集群
minikube start

# 使用Docker驱动启动（推荐）
minikube start --driver=docker

# 查看状态
minikube status

# 停止集群
minikube stop

# 删除集群
minikube delete

Kind（Kubernetes in Docker）使用Docker容器作为节点，启动速度快。

# 安装Kind
# macOS
brew install kind

# Linux
curl -Lo ./kind https://kind.sigs.k8s.io/dl/v0.20.0/kind-linux-amd64
chmod +x ./kind
sudo mv ./kind /usr/local/bin/kind

# 创建集群
kind create cluster

# 创建多节点集群
cat <<EOF | kind create cluster --config=-
kind: Cluster
apiVersion: kind.x-k8s.io/v1alpha4
nodes:
- role: control-plane
- role: worker
- role: worker
EOF

# 查看集群
kind get clusters

# 删除集群
kind delete cluster

Docker Desktop 内置Kubernetes支持，一键启用。

# 启用步骤：
# 1. 打开Docker Desktop
# 2. 进入Settings -> Kubernetes
# 3. 勾选 "Enable Kubernetes"
# 4. 点击 "Apply & Restart"

# 验证安装
kubectl cluster-info
kubectl get nodes

K3s 是轻量级Kubernetes发行版，资源占用少。

# 安装K3s（单节点）
curl -sfL https://get.k3s.io | sh -

# 检查状态
sudo systemctl status k3s

# 配置kubectl
mkdir -p ~/.kube
sudo cp /etc/rancher/k3s/k3s.yaml ~/.kube/config
sudo chown $(id -u):$(id -g) ~/.kube/config

# 验证
kubectl get nodes

安装kubectl

kubectl是Kubernetes的命令行工具，用于与集群交互：

# macOS
brew install kubectl

# Linux
curl -LO "https://dl.k8s.io/release/$(curl -L -s https://dl.k8s.io/release/stable.txt)/bin/linux/amd64/kubectl"
chmod +x kubectl
sudo mv kubectl /usr/local/bin/

# Windows
choco install kubernetes-cli

# 验证安装
kubectl version --client

# 配置命令补全（bash）
echo 'source <(kubectl completion bash)' >> ~/.bashrc
source ~/.bashrc

# 配置命令补全（zsh）
echo 'source <(kubectl completion zsh)' >> ~/.zshrc
source ~/.zshrc

# 设置别名
echo 'alias k=kubectl' >> ~/.bashrc
echo 'complete -o default -F __start_kubectl k' >> ~/.bashrc

验证环境

# 查看集群信息
kubectl cluster-info

# 查看节点状态
kubectl get nodes

# 查看所有命名空间
kubectl get namespaces

# 查看系统组件状态
kubectl get pods -n kube-system

kubectl基本操作

命令结构

kubectl命令的基本格式：

kubectl [command] [TYPE] [NAME] [flags]
🔄 正在渲染 Mermaid 图表...
flowchart LR
    CMD[kubectl] --> VERB[command<br/>动作]
    VERB --> TYPE[TYPE<br/>资源类型]
    TYPE --> NAME[NAME<br/>资源名称]
    NAME --> FLAGS[flags<br/>可选参数]

    VERB -.-> V1[get]
    VERB -.-> V2[create]
    VERB -.-> V3[delete]
    VERB -.-> V4[describe]
    VERB -.-> V5[apply]

    TYPE -.-> T1[pod]
    TYPE -.-> T2[service]
    TYPE -.-> T3[deployment]
    TYPE -.-> T4[node]

常用命令速查

# 查看所有Pod
kubectl get pods

# 查看所有命名空间的Pod
kubectl get pods -A
kubectl get pods --all-namespaces

# 详细输出
kubectl get pods -o wide

# YAML格式输出
kubectl get pod nginx -o yaml

# JSON格式输出
kubectl get pod nginx -o json

# 自定义列输出
kubectl get pods -o custom-columns=NAME:.metadata.name,STATUS:.status.phase

# 持续监视
kubectl get pods -w

# 按标签筛选
kubectl get pods -l app=nginx

# 查看多种资源
kubectl get pods,services,deployments
# 从YAML文件创建
kubectl create -f pod.yaml

# 声明式创建/更新
kubectl apply -f deployment.yaml

# 从目录创建
kubectl apply -f ./manifests/

# 从URL创建
kubectl apply -f https://example.com/nginx.yaml

# 快速创建Deployment
kubectl create deployment nginx --image=nginx

# 快速创建Service
kubectl expose deployment nginx --port=80 --type=NodePort

# 创建命名空间
kubectl create namespace dev
# 编辑资源（打开编辑器）
kubectl edit deployment nginx

# 打补丁更新
kubectl patch deployment nginx -p '{"spec":{"replicas":3}}'

# 设置镜像
kubectl set image deployment/nginx nginx=nginx:1.20

# 扩缩容
kubectl scale deployment nginx --replicas=5

# 添加标签
kubectl label pod nginx env=prod

# 添加注解
kubectl annotate pod nginx description="web server"
# 删除单个资源
kubectl delete pod nginx

# 从文件删除
kubectl delete -f pod.yaml

# 删除指定标签的资源
kubectl delete pods -l app=nginx

# 删除命名空间及其所有资源
kubectl delete namespace dev

# 强制删除
kubectl delete pod nginx --force --grace-period=0

# 删除所有Pod
kubectl delete pods --all
# 查看详细信息
kubectl describe pod nginx

# 查看日志
kubectl logs nginx

# 实时跟踪日志
kubectl logs -f nginx

# 查看前一个容器的日志
kubectl logs nginx --previous

# 多容器Pod指定容器
kubectl logs nginx -c sidecar

# 进入容器
kubectl exec -it nginx -- /bin/bash

# 执行单条命令
kubectl exec nginx -- ls /usr/share/nginx/html

# 端口转发
kubectl port-forward pod/nginx 8080:80

# 复制文件
kubectl cp nginx:/etc/nginx/nginx.conf ./nginx.conf

资源类型速查

# 查看所有资源类型
kubectl api-resources

实战演练

第一个Pod

创建一个简单的Nginx Pod：

# nginx-pod.yaml
apiVersion: v1
kind: Pod
metadata:
  name: nginx-pod
  labels:
    app: nginx
    env: demo
spec:
  containers:
  - name: nginx
    image: nginx:1.24
    ports:
    - containerPort: 80
    resources:
      requests:
        memory: "64Mi"
        cpu: "100m"
      limits:
        memory: "128Mi"
        cpu: "200m"
# 创建Pod
kubectl apply -f nginx-pod.yaml

# 查看Pod状态
kubectl get pod nginx-pod

# 查看详细信息
kubectl describe pod nginx-pod

# 查看Pod日志
kubectl logs nginx-pod

# 进入Pod内部
kubectl exec -it nginx-pod -- /bin/bash

# 在Pod内查看进程
ps aux

# 退出Pod
exit

# 端口转发测试访问
kubectl port-forward pod/nginx-pod 8080:80

# 在另一个终端测试
curl http://localhost:8080

# 清理资源
kubectl delete pod nginx-pod

第一个Deployment

创建一个Nginx Deployment：

# nginx-deployment.yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: nginx-deployment
  labels:
    app: nginx
spec:
  replicas: 3
  selector:
    matchLabels:
      app: nginx
  template:
    metadata:
      labels:
        app: nginx
    spec:
      containers:
      - name: nginx
        image: nginx:1.24
        ports:
        - containerPort: 80
        resources:
          requests:
            memory: "64Mi"
            cpu: "100m"
          limits:
            memory: "128Mi"
            cpu: "200m"
# 创建Deployment
kubectl apply -f nginx-deployment.yaml

# 查看Deployment状态
kubectl get deployment nginx-deployment

# 查看ReplicaSet
kubectl get rs

# 查看Pod（会有3个）
kubectl get pods -l app=nginx

# 扩容到5个副本
kubectl scale deployment nginx-deployment --replicas=5

# 查看扩容结果
kubectl get pods -l app=nginx

# 更新镜像版本
kubectl set image deployment/nginx-deployment nginx=nginx:1.25

# 查看滚动更新状态
kubectl rollout status deployment/nginx-deployment

# 查看更新历史
kubectl rollout history deployment/nginx-deployment

# 回滚到上一版本
kubectl rollout undo deployment/nginx-deployment

# 清理
kubectl delete deployment nginx-deployment

创建Service暴露应用

# nginx-service.yaml
apiVersion: v1
kind: Service
metadata:
  name: nginx-service
spec:
  type: NodePort
  selector:
    app: nginx
  ports:
  - port: 80
    targetPort: 80
    nodePort: 30080
# 先创建Deployment
kubectl apply -f nginx-deployment.yaml

# 创建Service
kubectl apply -f nginx-service.yaml

# 查看Service
kubectl get svc nginx-service

# 查看Endpoints
kubectl get endpoints nginx-service

# 测试访问（Minikube）
minikube service nginx-service --url

# 或使用NodePort访问
curl http://<node-ip>:30080

# 清理
kubectl delete -f nginx-deployment.yaml
kubectl delete -f nginx-service.yaml

Pod状态异常

    START[Pod状态异常] --> CHECK{查看状态}

    CHECK --> PENDING[Pending]

    CRASH --> C1[应用启动失败]
    CRASH --> C2[健康检查失败]
    C1 --> C1S[查看日志 kubectl logs]
    C2 --> C2S[调整探针配置]

    IMAGE --> I1[镜像不存在]
    IMAGE --> I2[认证失败]
    I1 --> I1S[检查镜像名称和标签]
    I2 --> I2S[配置imagePullSecrets]

    ERROR --> E1[配置错误]
    E1 --> E1S[kubectl describe查看Events]

kubectl run tmp-shell --rm -i --tty --image nicolaka/netshoot -- /bin/bash
常见错误
  • CrashLoopBackOff：容器反复崩溃，检查应用日志
  • ImagePullBackOff：无法拉取镜像，检查镜像名称和仓库认证
  • Pending：Pod无法调度，检查资源配额和节点选择器
  • OOMKilled：内存超限被杀死，增加内存限制
