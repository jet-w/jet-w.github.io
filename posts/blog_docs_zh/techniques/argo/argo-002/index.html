第 2 章：Argo CD基础入门

学习目标
  • 理解GitOps的核心原则和优势
  • 掌握Argo CD的安装和基本配置
  • 学会创建Application实现应用部署
  • 熟练使用Argo CD UI和CLI操作

知识点

GitOps核心原则

GitOps是一种实现持续交付的方法，它使用Git作为声明式基础设施和应用程序的唯一真相来源。

mindmap
  root((GitOps原则))
    声明式
      基础设施即代码
      期望状态描述
      版本控制管理
    版本化与不可变
      Git作为真相源
      完整变更历史
      可审计可追溯
    自动拉取
      Agent主动拉取
      无需集群凭证暴露
      更安全的模式
    持续调和
      自动检测漂移
      自我修复
      确保一致性

核心概念

概念说明
Application代表一个部署的应用，包含源仓库和目标集群信息
Project应用的逻辑分组，用于权限控制
RepositoryGit仓库或Helm仓库的连接配置
Cluster目标Kubernetes集群的连接配置
Sync将Git状态同步到集群的操作
Refresh从Git拉取最新配置的操作
Health应用资源的健康状态

安装Argo CD

标准安装

# 创建命名空间
kubectl create namespace argocd

# 安装Argo CD
kubectl apply -n argocd -f https://raw.githubusercontent.com/argoproj/argo-cd/stable/manifests/install.yaml

# 等待Pod就绪
kubectl wait --for=condition=Ready pods --all -n argocd --timeout=300s

# 查看部署状态
kubectl get pods -n argocd
# NAME                                                READY   STATUS    RESTARTS   AGE
# argocd-application-controller-0                     1/1     Running   0          2m
# argocd-applicationset-controller-xxx                1/1     Running   0          2m
# argocd-dex-server-xxx                               1/1     Running   0          2m
# argocd-notifications-controller-xxx                 1/1     Running   0          2m
# argocd-redis-xxx                                    1/1     Running   0          2m
# argocd-repo-server-xxx                              1/1     Running   0          2m
# argocd-server-xxx                                   1/1     Running   0          2m

高可用安装

# 高可用模式安装（生产环境推荐）
kubectl apply -n argocd -f https://raw.githubusercontent.com/argoproj/argo-cd/stable/manifests/ha/install.yaml

Helm安装

# 添加Helm仓库
helm repo add argo https://argoproj.github.io/argo-helm
helm repo update

# 安装Argo CD
helm install argocd argo/argo-cd \
  --namespace argocd \
  --create-namespace \
  --set server.service.type=LoadBalancer \
  --set configs.params.server.insecure=true
# 自定义values.yaml
# argocd-values.yaml
server:
  replicas: 2
  service:
    type: LoadBalancer
  ingress:
    enabled: true
    hosts:
      - argocd.example.com
    tls:
      - secretName: argocd-tls
        hosts:
          - argocd.example.com

controller:
  replicas: 1

repoServer:
  replicas: 2

redis:
  enabled: true

configs:
  params:
    server.insecure: true
  repositories:
    - url: https://github.com/myorg/myapp.git
      name: myapp
helm install argocd argo/argo-cd -n argocd -f argocd-values.yaml

apiVersion: networking.k8s.io/v1
kind: Ingress
metadata:
  name: argocd-ingress
  namespace: argocd
  annotations:
    nginx.ingress.kubernetes.io/ssl-passthrough: "true"

  - hosts:
    - argocd.example.com
    secretName: argocd-tls

使用YAML创建

# guestbook-app.yaml
apiVersion: argoproj.io/v1alpha1
kind: Application
metadata:
  name: guestbook
  namespace: argocd
  # 应用删除时自动清理资源
  finalizers:
    - resources-finalizer.argocd.argoproj.io
spec:
  # 项目名称（default为内置项目）
  project: default

  # 源配置
  source:
    repoURL: https://github.com/argoproj/argocd-example-apps.git
    targetRevision: HEAD
    path: guestbook

  # 目标配置
  destination:
    server: https://kubernetes.default.svc
    namespace: guestbook

  # 同步策略
  syncPolicy:
    automated:
      prune: true       # 删除Git中不存在的资源
      selfHeal: true    # 自动修复漂移
      allowEmpty: false # 不允许空应用
    syncOptions:
      - CreateNamespace=true  # 自动创建命名空间
      - PruneLast=true       # 最后执行删除
      - ApplyOutOfSyncOnly=true  # 只同步变更的资源
    retry:
      limit: 5
      backoff:
        duration: 5s
        factor: 2
        maxDuration: 3m
# 应用配置
kubectl apply -f guestbook-app.yaml

# 查看应用状态
kubectl get applications -n argocd
argocd app get guestbook

使用CLI创建

# 创建应用
argocd app create guestbook \
  --repo https://github.com/argoproj/argocd-example-apps.git \
  --path guestbook \
  --dest-server https://kubernetes.default.svc \
  --dest-namespace guestbook \
  --sync-policy automated \
  --auto-prune \
  --self-heal

# 查看应用列表
argocd app list

# 查看应用详情
argocd app get guestbook

# 查看应用资源
argocd app resources guestbook

# 查看应用清单
argocd app manifests guestbook

同步操作

同步状态说明

🔄 正在渲染 Mermaid 图表...
stateDiagram-v2
    [*] --> OutOfSync: 检测到差异
    OutOfSync --> Syncing: 执行同步
    Syncing --> Synced: 同步成功
    Syncing --> Failed: 同步失败
    Synced --> OutOfSync: 配置变更
    Failed --> OutOfSync: 重试
    Synced --> [*]
状态说明
Synced集群状态与Git一致
OutOfSync集群状态与Git不一致
Unknown无法确定同步状态

健康状态说明

状态说明
Healthy所有资源健康运行
Progressing资源正在部署中
Degraded资源运行异常
Suspended资源被暂停
Missing资源不存在
Unknown无法确定健康状态

手动同步

# 同步应用
argocd app sync guestbook

# 同步指定资源
argocd app sync guestbook --resource ':Deployment:guestbook-ui'

# 强制同步（忽略差异检查）
argocd app sync guestbook --force

# 模拟同步（不实际执行）
argocd app sync guestbook --dry-run

# 同步并等待完成
argocd app sync guestbook --wait

# 同步并等待健康
argocd app sync guestbook --wait --health

自动同步配置

apiVersion: argoproj.io/v1alpha1
kind: Application
metadata:
  name: myapp
  namespace: argocd
spec:
  project: default
  source:
    repoURL: https://github.com/myorg/myapp.git
    targetRevision: HEAD
    path: manifests
  destination:
    server: https://kubernetes.default.svc
    namespace: myapp
  syncPolicy:
    automated:
      # 自动修剪：删除Git中不存在的资源
      prune: true
      # 自我修复：检测到漂移时自动同步
      selfHeal: true
      # 不允许空应用（防止误删所有资源）
      allowEmpty: false
    syncOptions:
      # 自动创建命名空间
      - CreateNamespace=true
      # 验证资源配置
      - Validate=true
      # 替换而非patch
      - Replace=false
      # 服务端应用
      - ServerSideApply=true

配置仓库

添加Git仓库

# 添加公开仓库
argocd repo add https://github.com/argoproj/argocd-example-apps.git

# 添加私有仓库（HTTPS）
argocd repo add https://github.com/myorg/private-repo.git \
  --username <username> \
  --password <password>

# 添加私有仓库（SSH）
argocd repo add git@github.com:myorg/private-repo.git \
  --ssh-private-key-path ~/.ssh/id_rsa

# 添加私有仓库（Deploy Key）
argocd repo add git@github.com:myorg/private-repo.git \
  --ssh-private-key-path ./deploy-key

# 查看仓库列表
argocd repo list

使用Secret配置仓库

# 使用Secret配置私有仓库
apiVersion: v1
kind: Secret
metadata:
  name: private-repo
  namespace: argocd
  labels:
    argocd.argoproj.io/secret-type: repository
stringData:
  type: git
  url: https://github.com/myorg/private-repo.git
  username: git-username
  password: ghp_xxxxxxxxxxxx

---
# SSH密钥方式
apiVersion: v1
kind: Secret
metadata:
  name: private-repo-ssh
  namespace: argocd
  labels:
    argocd.argoproj.io/secret-type: repository
stringData:
  type: git
  url: git@github.com:myorg/private-repo.git
  sshPrivateKey: |
    -----BEGIN OPENSSH PRIVATE KEY-----
    ...
    -----END OPENSSH PRIVATE KEY-----

添加Helm仓库

# 添加公开Helm仓库
argocd repo add https://charts.bitnami.com/bitnami --type helm --name bitnami

# 添加私有Helm仓库
argocd repo add https://charts.example.com \
  --type helm \
  --name private-helm \
  --username admin \
  --password secret
# 使用Helm Chart的Application
apiVersion: argoproj.io/v1alpha1
kind: Application
metadata:
  name: nginx
  namespace: argocd
spec:
  project: default
  source:
    repoURL: https://charts.bitnami.com/bitnami
    chart: nginx
    targetRevision: 15.0.0
    helm:
      releaseName: nginx
      values: |
        replicaCount: 3
        service:
          type: ClusterIP
      parameters:
        - name: image.tag
          value: "1.25.0"
  destination:
    server: https://kubernetes.default.svc
    namespace: nginx
  syncPolicy:
    automated:
      prune: true
      selfHeal: true
    syncOptions:
      - CreateNamespace=true

实战演练

部署示例应用

# 1. 创建应用
kubectl apply -f - <<EOF
apiVersion: argoproj.io/v1alpha1
kind: Application
metadata:
  name: demo-app
  namespace: argocd
spec:
  project: default
  source:
    repoURL: https://github.com/argoproj/argocd-example-apps.git
    targetRevision: HEAD
    path: guestbook
  destination:
    server: https://kubernetes.default.svc
    namespace: demo
  syncPolicy:
    syncOptions:
      - CreateNamespace=true
EOF

# 2. 查看应用状态
argocd app get demo-app

# 3. 手动同步
argocd app sync demo-app

# 4. 等待同步完成
argocd app wait demo-app --sync --health

# 5. 查看部署的资源
kubectl get all -n demo

# 6. 访问应用
kubectl port-forward svc/guestbook-ui -n demo 8081:80
# 浏览器访问 http://localhost:8081

使用Kustomize部署

# 项目结构
# myapp/
# ├── base/
# │   ├── deployment.yaml
# │   ├── service.yaml
# │   └── kustomization.yaml
# └── overlays/
#     ├── development/
#     │   └── kustomization.yaml
#     └── production/
#         └── kustomization.yaml

# Application配置
apiVersion: argoproj.io/v1alpha1
kind: Application
metadata:
  name: myapp-production
  namespace: argocd
spec:
  project: default
  source:
    repoURL: https://github.com/myorg/myapp.git
    targetRevision: main
    path: overlays/production
    # Kustomize配置
    kustomize:
      namePrefix: prod-
      commonLabels:
        env: production
      images:
        - name: myapp
          newName: gcr.io/myorg/myapp
          newTag: v1.2.3
  destination:
    server: https://kubernetes.default.svc
    namespace: production
  syncPolicy:
    automated:
      prune: true
      selfHeal: true

使用Helm部署

apiVersion: argoproj.io/v1alpha1
kind: Application
metadata:
  name: prometheus
  namespace: argocd
spec:
  project: default
  source:
    repoURL: https://prometheus-community.github.io/helm-charts
    chart: kube-prometheus-stack
    targetRevision: 45.0.0
    helm:
      releaseName: prometheus
      # 使用values文件
      valueFiles:
        - values-production.yaml
      # 内联values
      values: |
        prometheus:
          prometheusSpec:
            retention: 30d
            storageSpec:
              volumeClaimTemplate:
                spec:
                  accessModes: ["ReadWriteOnce"]
                  resources:
                    requests:
                      storage: 50Gi
        grafana:
          adminPassword: secret
          persistence:
            enabled: true
            size: 10Gi
      # 参数覆盖
      parameters:
        - name: alertmanager.enabled
          value: "true"
  destination:
    server: https://kubernetes.default.svc
    namespace: monitoring
  syncPolicy:
    automated:
      prune: true
      selfHeal: true
    syncOptions:
      - CreateNamespace=true
      - ServerSideApply=true

常见问题排查

同步失败

# 查看同步状态
argocd app get myapp

# 查看详细日志
argocd app logs myapp

# 查看资源事件
kubectl describe application myapp -n argocd

# 检查仓库连接
argocd repo get https://github.com/myorg/myapp.git

# 强制刷新
argocd app get myapp --refresh
argocd app get myapp --hard-refresh

健康检查失败

# 查看资源健康状态
argocd app resources myapp

# 查看具体资源状态
kubectl describe deployment myapp -n production
kubectl get events -n production --sort-by='.lastTimestamp'

# 查看Pod日志
kubectl logs -l app=myapp -n production

权限问题

# 检查Argo CD的ServiceAccount权限
kubectl auth can-i create deployments --as system:serviceaccount:argocd:argocd-application-controller -n target-namespace

# 查看RBAC配置
kubectl get clusterrolebinding -l app.kubernetes.io/part-of=argocd
注意事项
  1. 初始密码安全: 首次登录后立即修改admin密码
  2. 仓库凭证: 私有仓库凭证以Secret形式安全存储
  3. 同步策略: 生产环境建议先手动同步，验证后再开启自动同步
  4. 资源限制: 为Argo CD组件配置适当的资源限制
