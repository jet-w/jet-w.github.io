第 4 章：服务发现与负载均衡

学习目标
  • 掌握Service的四种类型及其使用场景
  • 理解Kubernetes DNS和服务发现机制
  • 学会配置Ingress实现七层负载均衡
  • 熟练进行服务间的网络通信配置

知识点

为什么需要Service

在Kubernetes中，Pod是动态的，可能随时被创建或销毁。每个Pod都有自己的IP地址，但这些IP地址不是固定的。Service为一组Pod提供了一个稳定的访问入口。

Service的工作原理

Service通过Label Selector选择后端Pod，kube-proxy负责将流量转发到正确的Pod。

Service四种类型

🔄 正在渲染 Mermaid 图表...
mindmap
  root((Service类型))
    ClusterIP
      默认类型
      集群内部访问
      虚拟IP
    NodePort
      节点端口暴露
      外部可访问
      端口范围30000-32767
    LoadBalancer
      云厂商负载均衡器

ClusterIP Service

ClusterIP是默认的Service类型，只能在集群内部访问。

创建ClusterIP Service

# web-deployment.yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: web-app
spec:
  replicas: 3
  selector:
    matchLabels:
      app: web
  template:
    metadata:
      labels:
        app: web
    spec:
      containers:
      - name: nginx
        image: nginx:1.20
        ports:
        - containerPort: 80
---
# web-service.yaml
apiVersion: v1
kind: Service
metadata:
  name: web-service
spec:
  type: ClusterIP  # 默认类型，可省略
  selector:
    app: web       # 选择 label 为 app=web 的 Pod
  ports:
  - name: http
    port: 80       # Service 端口
    targetPort: 80 # Pod 端口
    protocol: TCP
# 创建 Deployment 和 Service
kubectl apply -f web-deployment.yaml
kubectl apply -f web-service.yaml

# 查看 Service
kubectl get svc web-service
# NAME          TYPE        CLUSTER-IP      EXTERNAL-IP   PORT(S)   AGE
# web-service   ClusterIP   10.96.123.45    <none>        80/TCP    5s

# 查看 Service 详情
kubectl describe svc web-service

# 查看 Endpoints（后端Pod列表）
kubectl get endpoints web-service
# NAME          ENDPOINTS                                      AGE
# web-service   10.244.1.5:80,10.244.2.6:80,10.244.3.7:80     5s

# 在集群内测试访问
kubectl run test-pod --image=busybox --rm -it --restart=Never -- wget -qO- http://web-service

多端口Service

apiVersion: v1
kind: Service
metadata:

spec:

无头服务（Headless Service）

Headless Service不分配ClusterIP，直接返回后端Pod的IP列表，常用于StatefulSet。

apiVersion: v1
kind: Service
metadata:
  name: headless-service
spec:
  clusterIP: None  # 关键：设置为None
  selector:
    app: database
  ports:
  - port: 3306
    targetPort: 3306
# 查看 Headless Service
kubectl get svc headless-service
# NAME               TYPE        CLUSTER-IP   EXTERNAL-IP   PORT(S)    AGE
# headless-service   ClusterIP   None         <none>        3306/TCP   5s

# DNS 查询返回所有 Pod IP
kubectl run test --image=busybox --rm -it --restart=Never -- nslookup headless-service
# Server:    10.96.0.10
# Address 1: 10.96.0.10 kube-dns.kube-system.svc.cluster.local
#
# Name:      headless-service
# Address 1: 10.244.1.10 pod-0.headless-service.default.svc.cluster.local
# Address 2: 10.244.2.11 pod-1.headless-service.default.svc.cluster.local
# Address 3: 10.244.3.12 pod-2.headless-service.default.svc.cluster.local

NodePort Service

NodePort在每个节点上开放一个端口，允许从集群外部访问Service。

flowchart LR

    External -->|NodeIP:30080| Node2[Node 2<br/>192.168.1.11:30080]
    External -->|NodeIP:30080| Node3[Node 3<br/>192.168.1.12:30080]

    Node1 --> Service[Service<br/>ClusterIP:80]
    Node2 --> Service
    Node3 --> Service

    Service --> Pod1[Pod 1]
    Service --> Pod2[Pod 2]
    Service --> Pod3[Pod 3]

创建NodePort Service

apiVersion: v1
kind: Service
metadata:
  name: nodeport-service
spec:
  type: NodePort
  selector:
    app: web
  ports:
  - port: 80          # Service 端口（集群内访问）
    targetPort: 80    # Pod 端口
    nodePort: 30080   # 节点端口（可选，不指定则自动分配）
# 应用配置
kubectl apply -f nodeport-service.yaml

# 查看 Service
kubectl get svc nodeport-service
# NAME               TYPE       CLUSTER-IP      EXTERNAL-IP   PORT(S)        AGE
# nodeport-service   NodePort   10.96.200.100   <none>        80:30080/TCP   5s

# 获取节点IP
kubectl get nodes -o wide

# 从外部访问（使用任意节点IP）
curl http://<NodeIP>:30080

NodePort配置选项

apiVersion: v1
kind: Service
metadata:
  name: nodeport-advanced
spec:
  type: NodePort
  selector:
    app: web
  ports:
  - port: 80
    targetPort: 80
    nodePort: 30080
  # 控制流量策略
  externalTrafficPolicy: Local  # Local: 只转发到本节点Pod，Cluster: 可跨节点转发
注意事项
  • NodePort端口范围默认为30000-32767
  • externalTrafficPolicy: Local可以保留客户端源IP，但可能导致负载不均衡
  • 生产环境建议使用LoadBalancer或Ingress替代NodePort

LoadBalancer Service

LoadBalancer类型在云环境中会自动创建云厂商的负载均衡器。

    LB --> Node1[Node 1]
    LB --> Node2[Node 2]
    LB --> Node3[Node 3]

    Node1 --> Service[Service<br/>ClusterIP]

    Service --> Pod2[Pod 2]

创建LoadBalancer Service

apiVersion: v1
kind: Service
metadata:
  name: loadbalancer-service
  annotations:
    # 云厂商特定注解（以AWS为例）
    service.beta.kubernetes.io/aws-load-balancer-type: "nlb"
    service.beta.kubernetes.io/aws-load-balancer-internal: "false"
spec:
  type: LoadBalancer
  selector:
    app: web
  ports:
  - port: 80
    targetPort: 80
  # 可选：指定负载均衡器IP（需云厂商支持）
  # loadBalancerIP: 203.0.113.10
# 应用配置
kubectl apply -f loadbalancer-service.yaml

# 查看 Service（等待 EXTERNAL-IP 分配）
kubectl get svc loadbalancer-service -w
# NAME                   TYPE           CLUSTER-IP      EXTERNAL-IP     PORT(S)        AGE
# loadbalancer-service   LoadBalancer   10.96.100.50    <pending>       80:31234/TCP   5s
# loadbalancer-service   LoadBalancer   10.96.100.50    203.0.113.10    80:31234/TCP   30s

# 通过外部IP访问
curl http://203.0.113.10

本地测试LoadBalancer（MetalLB）

在本地Kubernetes集群（如Minikube、Kind）中，可以使用MetalLB提供LoadBalancer功能。

# 安装 MetalLB

  - 192.168.1.240-192.168.1.250  # 可用IP范围

  name: default
  namespace: metallb-system
spec:
  ipAddressPools:
  - default-pool

ExternalName Service

ExternalName用于将Service映射到外部DNS名称，常用于访问集群外部服务。

apiVersion: v1
kind: Service
metadata:
  name: external-database
spec:
  type: ExternalName
  externalName: database.example.com  # 外部服务的DNS名称
# 集群内Pod可以通过 external-database 访问外部数据库
kubectl run test --image=busybox --rm -it --restart=Never -- nslookup external-database
# Name:      external-database
# Address 1: <database.example.com的IP地址>

访问外部固定IP服务

如果外部服务是固定IP而非域名，需要手动创建Endpoints。

# 无 Selector 的 Service
apiVersion: v1
kind: Service
metadata:
  name: external-service
spec:
  ports:
  - port: 3306
    targetPort: 3306
---
# 手动创建 Endpoints
apiVersion: v1
kind: Endpoints
metadata:
  name: external-service  # 必须与 Service 同名
subsets:
- addresses:
  - ip: 192.168.100.10  # 外部服务IP
  - ip: 192.168.100.11
  ports:
  - port: 3306

Ingress控制器

Ingress提供七层（HTTP/HTTPS）负载均衡，支持基于域名和路径的路由。

Ingress架构

    Ingress -->|host: api.example.com| SVC1[api-service]

安装Nginx Ingress Controller

# 使用 Helm 安装
helm repo add ingress-nginx https://kubernetes.github.io/ingress-nginx
helm repo update
helm install ingress-nginx ingress-nginx/ingress-nginx \
  --namespace ingress-nginx \
  --create-namespace

# 或使用 kubectl 安装
kubectl apply -f https://raw.githubusercontent.com/kubernetes/ingress-nginx/controller-v1.8.1/deploy/static/provider/cloud/deploy.yaml

# 验证安装
kubectl get pods -n ingress-nginx
kubectl get svc -n ingress-nginx

创建Ingress规则

# 首先创建后端服务
apiVersion: apps/v1
kind: Deployment
metadata:
  name: web-app
spec:
  replicas: 2
  selector:
    matchLabels:
      app: web
  template:
    metadata:
      labels:
        app: web
    spec:
      containers:
      - name: nginx
        image: nginx
        ports:
        - containerPort: 80
---
apiVersion: v1
kind: Service
metadata:
  name: web-service
spec:
  selector:
    app: web
  ports:
  - port: 80
    targetPort: 80
---
# 创建 Ingress
apiVersion: networking.k8s.io/v1
kind: Ingress
metadata:
  name: web-ingress
  annotations:
    nginx.ingress.kubernetes.io/rewrite-target: /
spec:
  ingressClassName: nginx  # 指定 Ingress Controller
  rules:
  - host: web.example.com  # 域名
    http:
      paths:
      - path: /
        pathType: Prefix
        backend:
          service:
            name: web-service
            port:
              number: 80
# 应用配置
kubectl apply -f web-ingress.yaml

# 查看 Ingress
kubectl get ingress
# NAME          CLASS   HOSTS             ADDRESS         PORTS   AGE
# web-ingress   nginx   web.example.com   192.168.1.240   80      5s

# 本地测试（添加 hosts 记录）
echo "192.168.1.240 web.example.com" | sudo tee -a /etc/hosts

# 访问测试
curl http://web.example.com

HTTPS配置

# 生成自签名证书（生产环境建议使用 cert-manager）
openssl req -x509 -nodes -days 365 -newkey rsa:2048 \
  -keyout tls.key -out tls.crt \
  -subj "/CN=web.example.com"

# 创建 Secret
kubectl create secret tls web-tls-secret \
  --cert=tls.crt \
  --key=tls.key
apiVersion: networking.k8s.io/v1
kind: Ingress
metadata:
  name: https-ingress
  annotations:
    nginx.ingress.kubernetes.io/ssl-redirect: "true"
spec:
  ingressClassName: nginx
  tls:
  - hosts:
    - web.example.com
    secretName: web-tls-secret  # TLS证书Secret
  rules:
  - host: web.example.com
    http:
      paths:
      - path: /
        pathType: Prefix
        backend:
          service:
            name: web-service
            port:
              number: 80

Ingress高级配置

apiVersion: networking.k8s.io/v1
kind: Ingress
metadata:
  name: advanced-ingress
  annotations:
    # 重写路径
    nginx.ingress.kubernetes.io/rewrite-target: /$2
    # 限速
    nginx.ingress.kubernetes.io/limit-rps: "10"
    nginx.ingress.kubernetes.io/limit-connections: "5"
    # 超时配置
    nginx.ingress.kubernetes.io/proxy-connect-timeout: "30"
    nginx.ingress.kubernetes.io/proxy-read-timeout: "60"
    # 请求体大小限制
    nginx.ingress.kubernetes.io/proxy-body-size: "10m"
    # 开启CORS
    nginx.ingress.kubernetes.io/enable-cors: "true"
    nginx.ingress.kubernetes.io/cors-allow-origin: "*"
spec:
  ingressClassName: nginx
  rules:
  - host: api.example.com
    http:
      paths:
      - path: /api(/|$)(.*)
        pathType: Prefix
        backend:
          service:
            name: api-service
            port:
              number: 80

网络策略（NetworkPolicy）

NetworkPolicy用于控制Pod之间的网络流量，实现网络隔离。

NetworkPolicy工作原理

🔄 正在渲染 Mermaid 图表...
flowchart TB
    subgraph NS1["Namespace: frontend"]
        FE[Frontend Pod<br/>app=frontend]
    end

    subgraph NS2["Namespace: backend"]
        BE[Backend Pod<br/>app=backend]
        NP[NetworkPolicy]
    end

    subgraph NS3["Namespace: database"]
        DB[Database Pod<br/>app=db]
    end

    FE -->|✅ 允许| BE
    BE -->|✅ 允许| DB
    FE -.->|❌ 拒绝| DB

    NP -->|规则: 只允许 backend 访问| DB

创建NetworkPolicy

# 拒绝所有入站流量（默认隔离）
apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata:
  name: deny-all-ingress
  namespace: production
spec:
  podSelector: {}  # 选择所有Pod
  policyTypes:
  - Ingress
  # 没有 ingress 规则，表示拒绝所有入站
---
# 允许特定流量
apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata:
  name: backend-policy
  namespace: production
spec:
  podSelector:
    matchLabels:
      app: backend
  policyTypes:
  - Ingress
  - Egress
  ingress:
  # 允许来自 frontend 的流量
  - from:
    - podSelector:
        matchLabels:
          app: frontend
    ports:
    - protocol: TCP
      port: 8080
  egress:
  # 允许访问 database
  - to:
    - podSelector:
        matchLabels:
          app: database
    ports:
    - protocol: TCP
      port: 5432
  # 允许 DNS 查询
  - to:
    - namespaceSelector: {}
      podSelector:
        matchLabels:
          k8s-app: kube-dns
    ports:
    - protocol: UDP
      port: 53

常见NetworkPolicy场景

# 场景1：只允许同namespace的Pod访问
apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata:
  name: same-namespace-only
spec:
  podSelector: {}
  policyTypes:
  - Ingress
  ingress:
  - from:
    - podSelector: {}  # 同namespace的所有Pod

---
# 场景2：允许特定namespace访问
apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata:
  name: allow-from-monitoring
  namespace: production
spec:
  podSelector:
    matchLabels:
      app: web
  policyTypes:
  - Ingress
  ingress:
  - from:
    - namespaceSelector:
        matchLabels:
          name: monitoring
    ports:
    - protocol: TCP
      port: 9090

---
# 场景3：允许外部IP访问
apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata:
  name: allow-external-ip
spec:
  podSelector:
    matchLabels:
      app: public-api
  policyTypes:
  - Ingress
  ingress:
  - from:
    - ipBlock:
        cidr: 203.0.113.0/24
        except:
        - 203.0.113.100/32
    ports:
    - protocol: TCP
      port: 443

常见问题排查

Service无法访问

# 检查 Service 配置
kubectl describe svc <service-name>

# 检查 Endpoints 是否正确
kubectl get endpoints <service-name>
# 如果 ENDPOINTS 为空，检查：
# 1. selector 标签是否匹配 Pod
# 2. Pod 是否处于 Running 状态
# 3. Pod 的 readinessProbe 是否通过

# 检查 Pod 标签
kubectl get pods --show-labels

# 测试直接访问 Pod
kubectl get pods -o wide
kubectl run test --image=busybox --rm -it -- wget -qO- http://<Pod-IP>:<Port>

DNS解析失败

# 检查 CoreDNS 状态
kubectl get pods -n kube-system -l k8s-app=kube-dns

# 查看 CoreDNS 日志
kubectl logs -n kube-system -l k8s-app=kube-dns

# 测试 DNS 解析
kubectl run dns-test --image=busybox:1.28 --rm -it -- nslookup kubernetes

# 检查 Pod 的 DNS 配置
kubectl exec <pod-name> -- cat /etc/resolv.conf

Ingress不工作

# 检查 Ingress Controller 状态
kubectl get pods -n ingress-nginx

# 查看 Ingress Controller 日志
kubectl logs -n ingress-nginx -l app.kubernetes.io/name=ingress-nginx

# 检查 Ingress 配置
kubectl describe ingress <ingress-name>

# 验证 Ingress Controller Service
kubectl get svc -n ingress-nginx

# 测试直接访问 Ingress Controller
curl -H "Host: your-domain.com" http://<Ingress-Controller-IP>
常见陷阱
  1. Selector不匹配: Service的selector必须与Pod的label完全匹配
  2. 端口配置错误: 注意区分port（Service端口）和targetPort（Pod端口）
  3. NetworkPolicy过于严格: 记得允许DNS流量（UDP 53端口）
  4. Ingress Class未指定: Kubernetes 1.18+需要指定ingressClassName
